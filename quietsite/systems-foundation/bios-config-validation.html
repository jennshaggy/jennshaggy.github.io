BIOS Configuration & System Validation

Firmware-level configuration for security and virtualization, followed by multi-layer storage health validation.
Status: Complete

Overview#

After hardware assembly, the system required firmware-level configuration before OS deployment. This included enabling TPM 2.0 for BitLocker support, configuring Intel Virtualization Technology for hypervisor workloads, and validating storage integrity at multiple diagnostic layers.

Security starts in firmware. Get it wrong here, and the OS inherits constraints it can't fix.

Objectives#

  • Enable TPM 2.0 for secure boot and encryption
  • Configure Intel VT-x and VT-d for virtualization
  • Verify storage detection at firmware level
  • Validate storage health using OS-level diagnostics
  • Document baseline system state

Work Performed#

BIOS Access#

System powered on, F2 pressed during POST to enter BIOS setup. Dell UEFI interface loaded. Firmware version confirmed: 1.10.0.

TPM 2.0 Configuration#

Navigated to Security → TPM 2.0 Security and enabled:

  • TPM 2.0 Security: ON — Makes Trusted Platform Module visible to OS
  • Attestation Enable: ON — Allows TPM signing operations for secure boot
  • Key Storage Enable: ON — Permits TPM to store encryption keys
  • SHA-256: Enabled — Uses SHA-256 hashing for PCR measurements (stronger than SHA-1)

Changes saved. TPM now available to Windows for BitLocker and secure boot validation.

Virtualization Configuration#

Navigated to Virtualization Support and enabled:

  • Intel Virtualization Technology (VT-x): ON — Hardware-assisted virtualization for hypervisors
  • VT for Direct I/O (VT-d): ON — Allows VMs to directly access I/O devices
  • Intel Trusted Execution Technology (TXT): ON — Provides measured boot for secure VM launch

This configuration enables full hypervisor functionality including nested virtualization and PCI passthrough.

Storage Detection#

Verified all drives detected under Storage → SATA/NVMe Devices:

  • Primary M.2 NVMe SSD recognized with correct capacity
  • M.2 slot configuration confirmed (PCIe Gen4 x4 operational)

Boot order set: NVMe SSD first, USB and network boot disabled. Settings saved and system rebooted.

Storage Health Validation#

After Windows installation, storage health validated using multiple diagnostic tools.

Disk Management#

Opened diskmgmt.msc and verified:

  • All drives visible and correctly partitioned
  • Drive letters assigned correctly
  • No unallocated space or partition errors
  • GPT partition scheme confirmed for UEFI boot

CHKDSK — Filesystem Integrity#

Ran chkdsk /F from Administrator command prompt. Tool scheduled for next reboot.

On reboot, CHKDSK completed all five verification stages. Result: No errors found. Filesystem integrity confirmed.

DiskCheckup — SMART Analysis#

Used PassMark DiskCheckup to read SMART data from NVMe drive:

  • Power-On Hours: Low (new drive)
  • Temperature: Within normal operating range
  • Reallocated Sectors: 0 (no bad blocks)
  • Pending Sectors: 0
  • Overall Health Status: PASSED

No signs of wear or imminent failure.

Windows Error Checking#

Ran Windows Error Checking via C: Properties → Tools → Check.

Result: No errors detected. Filesystem clean.

Outcome#

Firmware configured for security and virtualization. TPM enabled, Intel VT-x/VT-d operational. Storage validated at firmware and OS levels — no errors, no bad sectors, SMART data clean. System ready for production workloads.

Why It Matters#

BIOS configuration isn't optional. If TPM isn't enabled, BitLocker won't work. If virtualization extensions aren't enabled, hypervisors fail or run slowly. If storage issues exist but aren't caught early, they become data loss.

Checking at multiple layers — BIOS detection, OS scans, SMART attributes — is what catches problems before they matter.
