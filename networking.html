Network Architecture & Implementation

Home and small office network design, deployment, and remote management

Home Lab

A real Active Directory environment, built from scratch on bare metal, managed from a couch in Albuquerque.

The hardware

The host is a NanoNuc running Proxmox, a type-1 hypervisor sitting on the home network. Everything else runs as a VM on top of it. Boot into Proxmox and the lab furniture showroom opens. Boot into Kali and it’s pentest workstation mode. F7 picks the room.

The architecture

Four nodes, one domain:

DC01 runs Active Directory Domain Services and DNS. It is the domain controller for the lab, handling authentication and name resolution across the environment.

Getting the Windows Server VMs running on Proxmox requires VirtIO drivers. Without them, the VM can’t see its network adapter or storage controller. The virtio-win ISO handles it.

fileserver is a domain-joined Windows server providing shared file services. Folder redirection is configured via Group Policy, so the domain user’s Documents folder lives on the fileserver rather than the local machine. That is not a default. That is a deliberate configuration.

After the tools install and the fileserver joins the domain:

linuxvpn is an Ubuntu Server VM running Tailscale as both an exit node and a subnet router. This is the lab’s remote access layer. No router ports are open. No port-forwarding rules exist. Tailscale routes traffic through linuxvpn without touching the firewall, which means the lab is reachable from any trusted device without exposing anything publicly. Most people port-forward and call it a day. This is the other approach.

WIN11-CLIENT is a domain-joined Windows 11 workstation. It authenticates against DC01, has its Documents redirected to fileserver, and can be used to simulate a real end-user endpoint inside the domain.

A honeypot node is on the roadmap.

Remote access via Tailscale

With linuxvpn as the Tailscale gateway, the lab supports:

  • Remote access into the home network without opening router ports
  • Exit node routing (linuxvpn acts as a private VPN endpoint)
  • Subnet routing, so Tailscale-connected devices can reach the full lab LAN directly
  • Safer admin access to Proxmox, SSH, RDP, and internal web tools over Tailscale instead of the public internet
  • Simulating “remote worker” behavior: take the WIN11-CLIENT off-network and test internal resource access through the VPN

The practical end-state: the entire lab is reachable from a laptop at a coffee shop with no public-facing attack surface.

Operating it

Managing a lab is different from building one. Building is a project. Operating is a practice.

Group Policy handles folder redirection across the domain. Documents for every domain user route to the fileserver share automatically.

The monitoring plan covers authentication events, admin privilege assignments, account changes, Kerberos activity, and scan detection. Splunk dashboards are in progress. A honeypot node is queued once the baseline is solid.

Network security starts at the infrastructure layer. Proper topology, segmentation, and coverage optimization aren't just performance concerns - they're foundational security controls that determine what's reachable, what's isolated, and where the perimeter actually is.

Current Network (Albuquerque, NM)#

Deployed a 3-node TP-Link Deco 6E tri-band mesh network optimized for complete residential coverage with intentional signal boundaries. The ISP-provided router was immediately placed in bridge mode and its hidden hotspot broadcast functionality - designed to extend the ISP's public network into customer homes - was disabled.

ISP router (left) configured in bridge mode, Deco 6E mesh node (right) handling all routing and wireless

Network segmentation isolates IoT devices on a separate SSID with distinct credentials. Guest network capabilities were disabled entirely to reduce attack surface. Coverage was validated and optimized using RF heat mapping across the full residence.

Heat map validation - download speeds optimized across interior space, signal intentionally cuts off at property boundary

Key outcomes: Zero dead zones inside the residence. Network signal terminates at the property line - not by accident, but by design. IoT devices cannot reach the primary network. ISP equipment operates as a transparent bridge with no broadcast capabilities.

Network Design Approach#

Networks aren't appliances. They're infrastructure that determines what's accessible, what's segmented, and where trust boundaries exist. Proper deployment requires understanding RF propagation, physical construction constraints, device isolation requirements, and long-term maintainability. The goal isn't just connectivity - it's controlled, segmented, validated connectivity that fails closed when things break.
