Boogeyman – Initial Access Investigation

Platform: TryHackMe
Lab: Boogeyman Part 1
Category: SOC Investigation
Focus: Phishing → Endpoint Compromise → Data Exfiltration
Tools: Thunderbird, Wireshark, Tshark, jq, LNKParse3, Linux CLI
Artifacts: dump.eml, powershell.json, capture.pcapng

Overview

This investigation analyzes a targeted phishing attack against Quick Logistics LLC. A finance employee, Julianne, received a malicious email disguised as a follow-up invoice from a trusted business partner.

Execution of the attachment initiated a multi-stage compromise involving malicious PowerShell execution, attacker-controlled file downloads, credential harvesting, command-and-control activity, and attempted data exfiltration.

The investigation required analyzing artifacts from three sources: email artifact, PowerShell endpoint logs, and network packet capture.

Investigation Environment

Artifacts provided for analysis:

dump.eml – Copy of the phishing email

powershell.json – PowerShell execution logs extracted from Windows Event Logs

capture.pcapng – Network traffic capture from the compromised workstation

Analysis tools available: Thunderbird (email reconstruction), LNKParse3 (shortcut file forensic analysis), Wireshark/Tshark (packet analysis), jq (JSON log parsing), Linux CLI utilities

Phase 1 – Email Analysis

The investigation began with analysis of the phishing email stored as dump.eml. The message impersonated a business partner and referenced an unpaid invoice. The attached archive contained a malicious shortcut file.

After extraction, the malicious shortcut file was analyzed using LNKParse3. The LNK metadata revealed a command line payload designed to execute a PowerShell script.

Phase 2 – Endpoint Activity Analysis

PowerShell logs were analyzed from powershell.json. Since the logs were JSON formatted, the jq utility was used to parse and sort events. Analysis revealed that the malicious shortcut executed a PowerShell command that downloaded additional attacker tooling. The attacker then performed reconnaissance and credential harvesting activities on the compromised workstation.

Phase 3 – Attacker Activity

PowerShell logs revealed download of attacker utilities, execution of enumeration tooling, access to sensitive credential storage files, and staging of sensitive data for exfiltration. A notable discovery was access to a KeePass password database file (.kdbx), which contains encrypted credential storage. The attacker encoded the stolen data before transmitting it to an external host.

Phase 4 – Network Traffic Analysis

The packet capture file capture.pcapng was analyzed using Wireshark. The investigation focused on network connections associated with suspicious domains discovered in PowerShell logs, command-and-control traffic, and file exfiltration attempts. Command streams within the capture revealed the attacker executing commands remotely and receiving output through HTTP communication.

Attack Chain Reconstruction

Initial Access – Phishing email containing malicious attachment
Execution – Shortcut file executes embedded PowerShell command
Persistence / Tooling – PowerShell downloads attacker utilities
Credential Access – KeePass database accessed
Command and Control – Attacker communicates with compromised host
Exfiltration – Sensitive data encoded and transmitted to external server

Key Findings

The phishing attack targeted employees within the finance department, indicating a focused social engineering campaign. The malicious attachment leveraged PowerShell execution to download additional attacker tooling. Sensitive credential data stored within a KeePass password database was accessed and exfiltrated. Network traffic analysis confirmed command-and-control communication and outbound transmission of encoded data.

Evidence & Validation

Investigation results validating phishing analysis and PowerShell execution chain

PowerShell log analysis revealing attacker reconnaissance and credential access

Network packet capture confirming C2 communication and encoded data transmission

Boogeyman 2 – Memory Forensics & Persistence Investigation

Platform: TryHackMe
Lab: Boogeyman Part 2
Category: SOC Investigation
Focus: Spear Phishing → Memory Analysis → C2 → Persistence
Tools: Volatility, Olevba, Linux CLI
Artifacts: phishing email, memory dump

Overview

This investigation analyzes a second-stage Boogeyman intrusion against Quick Logistics LLC. After improving their defenses following the first attack, the organization was targeted again using a new phishing lure. This time, the attack focused on Human Resources. A malicious resume was delivered to an HR employee, resulting in compromise of the victim workstation.

This lab relied heavily on memory forensics to reconstruct attacker activity after execution.

Phase 1 – Spear Phishing Analysis

The attack began with a malicious email sent to a Human Resources employee. The phishing lure was tailored to the HR function by presenting the attachment as a job application or resume. Key artifacts identified included sender email address, victim employee email, attached malicious document, and MD5 hash of the attachment.

Phase 2 – Document and Macro Analysis

The malicious resume document was analyzed using Olevba to inspect embedded VBA macro content. The macro analysis revealed that the document reached out to an external URL to retrieve a second-stage payload. This confirmed that the document was not simply malicious in isolation, but part of a staged intrusion chain.

Phase 3 – Stage 2 Payload Execution

Memory analysis was used to determine what happened after the stage 2 payload was downloaded. Volatility allowed reconstruction of the process responsible for executing the stage 2 payload, the full file path of the payload, and the process tree. The stage 2 payload then initiated the next phase of the attack by downloading an additional malicious binary.

Phase 4 – C2 Establishment

Further memory analysis identified the malicious process responsible for establishing command-and-control communication. Artifacts recovered included PID of the malicious process, full file path of the binary, and IP address and port of the C2 server. This stage confirmed that the compromise progressed beyond simple document execution and into active attacker-controlled communication.

Phase 5 – Persistence

Shortly after establishing command-and-control, the attacker created persistence using a scheduled task. This allowed the attacker to maintain access even if the initial process terminated or the host was rebooted. The investigation identified the full scheduled task command used by the attacker.

Attack Chain Reconstruction

Initial Access – Spear phishing email sent to HR employee
Execution – Malicious resume document opened
Stage 2 Delivery – Macro downloads second-stage payload
Stage 2 Execution – Downloaded payload executed on host
Command and Control – Malicious binary initiates outbound C2 connection
Persistence – Scheduled task created to maintain access

Key Findings

The phishing campaign was more targeted than the first Boogeyman attack, showing increased tradecraft through role-specific social engineering. Memory forensics confirmed the execution path of the payload, the malicious child process chain, and the binary responsible for command-and-control. The attacker established persistence almost immediately after gaining remote control by creating a scheduled task.

Lab Verification

Memory analysis identifying process execution chain and C2 artifacts

VBA macro extraction and stage 2 payload download analysis

Scheduled task persistence and command-and-control connection details

Boogeyman 3 – Lateral Movement & Domain Compromise Investigation

Platform: TryHackMe
Lab: Boogeyman Part 3
Category: SOC Investigation
Focus: Persistence → Privilege Escalation → Lateral Movement → Domain Compromise
Tools: Elastic Stack (ELK), Kibana, Sysmon Logs, Linux CLI
Artifacts: Elastic SIEM logs, host telemetry

Overview

This investigation represents the final stage of the Boogeyman intrusion against Quick Logistics LLC. After successfully compromising a workstation and establishing persistence during earlier stages of the attack, the threat actor remained undetected within the environment. Using access to internal email accounts, the attacker launched a second phishing attempt targeting the CEO.

Using centralized logs from the Elastic Stack (ELK), the investigation focused on identifying the full scope of attacker activity, including persistence, privilege escalation, credential theft, lateral movement, and preparation for ransomware deployment.

Phase 1 – Initial Payload Execution

The investigation began by identifying the process responsible for executing the stage 1 payload delivered through the malicious attachment. Logs revealed the process responsible for initiating the payload execution, including the command-line activity used to implant a secondary file onto the host.

Phase 2 – Persistence

After executing the implanted payload, the attacker established persistence using a scheduled task. The scheduled task ensured that the malicious script would execute automatically, allowing the attacker to retain access even if the system restarted or the initial payload process terminated.

Phase 3 – Command and Control

Following successful execution and persistence, the attacker initiated command-and-control communication with an external host. The investigation identified the external IP address used for the connection, the network port used by the attacker, and the process responsible for establishing the connection.

Phase 4 – Privilege Escalation

Logs revealed that the attacker discovered the compromised system had local administrator privileges. To take advantage of this, the attacker executed a User Account Control (UAC) bypass technique to elevate privileges without triggering security prompts. This allowed the attacker to perform higher-privileged actions such as credential extraction and system-level operations.

Phase 5 – Credential Dumping

With elevated privileges, the attacker downloaded a credential dumping tool from a public GitHub repository. Using this tool, the attacker extracted credentials from the compromised system. Credential harvesting allowed the attacker to expand their access beyond the initially compromised machine.

Phase 6 – Lateral Movement

Using the stolen credentials, the attacker attempted to access other systems within the network. Logs revealed that the attacker successfully accessed a remote machine using the harvested credentials. During this stage the attacker enumerated accessible network shares, accessed a file stored on a remote system, and obtained additional credentials.

Phase 7 – Second Machine Compromise

The attacker used the newly discovered credentials to compromise another machine within the network. Analysis of process activity revealed the parent process responsible for executing the malicious command on the second host. Once inside this system, the attacker again performed credential dumping to extract additional account hashes.

Phase 8 – Domain Controller Access

Eventually the attacker reached a system with domain-level access. At this stage the attacker performed a DCSync attack, which allowed them to replicate domain controller authentication data and retrieve password hashes from Active Directory. The investigation revealed that multiple account hashes were extracted during this operation.

Phase 9 – Ransomware Staging

After achieving domain-level access, the attacker attempted to download a remote binary intended to deploy ransomware. The investigation identified the remote location used to retrieve the ransomware payload. Although the ransomware execution was not completed during the timeframe analyzed, this final step confirmed that the attacker's objective was likely full network compromise followed by ransomware deployment.

Attack Chain Reconstruction

Initial Compromise – Phishing email targeting CEO
Execution – Malicious attachment executes stage 1 payload
Persistence – Scheduled task created to maintain access
Command and Control – Outbound connection established to attacker infrastructure
Privilege Escalation – UAC bypass executed to obtain elevated privileges
Credential Access – Credential dumping tool downloaded from GitHub
Lateral Movement – Stolen credentials used to access additional machines
Domain Compromise – DCSync attack used to dump domain credential hashes
Ransomware Preparation – Remote binary downloaded for ransomware deployment

Key Findings

The Boogeyman intrusion demonstrates a structured multi-stage attack designed to progress from initial access to domain compromise. The attacker successfully leveraged phishing-based initial access, persistence through scheduled tasks, privilege escalation through UAC bypass, credential dumping using publicly available tools, lateral movement using stolen credentials, and domain credential replication via DCSync. The final phase of the attack involved preparation for ransomware deployment.

Lab Verification

SIEM analysis revealing privilege escalation and credential harvesting activity

Lateral movement tracking across compromised systems

DCSync attack against domain controller and ransomware deployment staging
